# morning-post

Одноразовый скрипт: раз в день заходит на inp.one, берёт снапшот роя монет
(`window.__HOT_COINS_SNAPSHOT__`, флаг `?snapshot=1`) и скриншот графика,
собирает пост по шаблону (**без ИИ** в v1 — текст только из подстановок в
`phrases.ts`) и публикует его в Telegram. Запустился → сделал пост (или упал
с алертом) → завершился. Расписание — снаружи, через cron на VPS.

Подробное ТЗ и обоснования архитектурных решений — `plan/Start-build.md`.

## Как это устроено (коротко)

```
capture.ts   → снапшот + PNG с inp.one (Playwright) или из fixtures/ (SNAPSHOT_FILE)
facts.ts     → computeFacts(snapshot, history): чистые числа/факты, включая streak
phrases.ts   → словарь фраз по веткам, ≥3 варианта на ветку
render.ts    → buildParagraphs/buildCaption: HTML-caption ≤1024 символов
state.ts     → атомарное чтение/запись state.json, идемпотентность
telegram.ts  → sendPhoto/sendMessage, 3 ретрая на 429/5xx
alert.ts     → sendAlert админу: отдельный путь, не зависит от facts/render
index.ts     → склеивает всё, обрабатывает DRY_RUN/--force/ошибки
```

Вся логика фактов и текста — чистые функции без сети и браузера (тесты в
`tests/`, без флака). Всё "грязное" — Playwright, Telegram, файлы — изолировано
в своих модулях.

## Быстрый старт (Windows)

```bash
npm i
npx playwright install chromium
copy .env.example .env
```

Заполни в `.env` как минимум `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_CHAT_ID` —
без них скрипт не стартует вообще (без адресата для алертов защищаться не от
чего). `TELEGRAM_TARGET_CHAT_ID` нужен только для реальной публикации.

```bash
npm run typecheck
npm test
npm run dry                                        # снапшот с реального SITE_URL, ничего не публикует
npm run dry:fixture -- fixtures/green.json          # снапшот из файла, без браузера вообще
```

`DRY_RUN=1` (это значение и стоит в `.env.example`) печатает caption в stdout,
кладёт `./out/YYYY-MM-DD.png` и `./out/YYYY-MM-DD.facts.json` — сверить цифры
с картинкой глазами — и не трогает `state.json`.

**Никаких `VAR=значение npm run ...` в PowerShell/cmd** — не работает на
Windows. Все настройки — через `.env`; единственное исключение — путь к
фикстуре как позиционный аргумент, он работает в любой оболочке:
`npm run dry:fixture -- fixtures/red-streak.json`.

## Полный прогон против локального сайта (до мержа в `inp`)

Пока правка со снапшотом в `inp` живёт в ветке, весь пайплайн гоняется против
локально поднятого сайта в **прод-режиме** (`next build && next start`, не
`next dev` — другие тайминги рендера и другая картинка):

```
SITE_URL=http://localhost:3000/?snapshot=1
```

Повторные прогоны в один день блокирует идемпотентность — либо `--force`,
либо отдельный тестовый файл состояния:

```bash
STATE_FILE=./data/state.test.json npm run post
```

(команда с `VAR=...` выше — это Git Bash/POSIX-синтаксис для разового теста
самим разработчиком, не то, что уходит в документацию для конечного
Windows-скрипта — там только `.env` и позиционные аргументы, см. выше)

## Переменные окружения

| Переменная | Что | 
| --- | --- |
| `SITE_URL` | Адрес с `?snapshot=1` — без флага снапшота в `window` не будет |
| `CHART_SELECTOR` | Селектор контейнера графика для скриншота, обычно `#hot-coins-chart` |
| `TELEGRAM_BOT_TOKEN` | Токен бота (тот же, что у news-radar) |
| `TELEGRAM_TARGET_CHAT_ID` | Куда уходит сам пост — на старте личный chat_id, позже id канала |
| `TELEGRAM_ADMIN_CHAT_ID` | Куда уходят алерты — всегда личка владельца, независимо от `TARGET` |
| `TZ` | `Europe/Moscow` — таймзона поста и расписания, должны совпадать |
| `STATE_FILE` | Путь к `state.json` |
| `DRY_RUN` | `1` — собрать пост, не публиковать; `0` — публиковать по-настоящему |
| `SNAPSHOT_FILE` | Путь к фикстуре — обходит браузер целиком (только для отладки) |
| `MIN_SWARM_SIZE` | Минимум монет в рое, чтобы считать снапшот готовым |

Кавычки вокруг `CHART_SELECTOR="#hot-coins-chart"` обязательны — `#` без
кавычек в `.env`-файле начинает комментарий, и значение придёт пустой строкой
(натуральная грабля, найдена на этом проекте на шаге 4).

## AI-генерация текста (v2)

Абзацы поста может писать модель вместо шаблона — `AI_ENABLED=1` включает
ветку, любой сбой (валидатор, таймаут, исчерпанный бюджет) откатывает на
шаблонную версию без остановки публикации. Подробности контракта, промпта и
валидатора — `plan/ai-start-integration.md` (не в git, локальный файл).

- **`AI_ALLOW_REAL_IN_DRY`** — при `DRY_RUN=1` запрос к модели по умолчанию
  не делается вообще, только шаблон: `DRY_RUN` сам по себе не гарантия от
  реальной траты. Ставить `AI_ALLOW_REAL_IN_DRY=1` вручную только на
  конкретный прогон обкатки, не держать включённым постоянно.
- **`AI_USAGE_REPORT`** (`daily` / `weekly` / `0`) — ежедневная (или
  недельная) сводка расхода и остатка баланса на `TELEGRAM_ADMIN_CHAT_ID`
  после каждой публикации.
- **`npm run ai:compare -- <fixture>|--all [--runs=N] [--chain=N]
  [--model=<id>] [--balance=N]`** — ручная сверка шаблонной и ИИ-версий на
  реальных запросах к модели, тратит кредиты. `--runs=N` — N независимых
  сэмплов одного дня; `--chain=N` — N дней подряд, где вывод каждого уходит
  в history следующего (проверка анти-повтора), эти два флага взаимно
  исключают друг друга. Это инструмент для локальной обкатки, не часть
  боевого пути. Отчёты уходят в `reports/` (отслеживается git-ом, в отличие
  от `out/`) — платный прогон воспроизводится только повторной тратой
  кредитов, а у игнорируемого каталога нет ни истории, ни отката.
- **`tools/` вне основного `tsconfig.json`** (не часть боевой сборки), но
  проверяется отдельно: `npm run typecheck:tools` (`tsc -p
  tsconfig.tools.json --noEmit`).
- **Уборка `out/`.** Единственный разрешённый способ — удаление файлов по
  возрасту: `find out -type f -mtime +90 -delete`. Удаление самого каталога
  `out/` запрещено.

## Как править тексты

Все формулировки — в `src/phrases.ts`, отдельно от логики ветвления
(`src/render.ts`). На каждую ветку минимум 3 варианта, выбор детерминирован
по дню года (`dayOfYear % variants.length`) — можно смело добавлять/убирать
варианты, тесты (`tests/render.test.ts`) проверяют принадлежность к нужному
набору, а не конкретный текст. Жёсткие запреты: без прогнозов, без советов
«покупать/продавать», без обещаний иксов, без хэштегов, никаких зашитых в
текст цифр — только подстановки из `Facts`.

## Как переключить пост в канал

Сменить `TELEGRAM_TARGET_CHAT_ID` в `.env` (или в секретах/env контейнера на
VPS) на id канала. Никаких правок кода — `TELEGRAM_ADMIN_CHAT_ID` при этом не
трогается, алерты как шли в личку владельцу, так и идут.

## Фикстуры

- `fixtures/real-day.json` — реальный снапшот с боевого сайта, дословно, не
  трогать руками.
- `fixtures/*.json` (кроме `real-day.json`) — его правленные копии,
  пересобираются скриптом `npm run fixtures:gen` (`tools/gen-fixtures.mjs`):
  red-стрик, red-первый день, green, mixed, boring, без BTC, без edge-пинов,
  граница `red/total == 0.6` ровно, тикеры `A&B`/`<b>X` для `escapeHtml`.
- `fixtures/history/*.json` — сценарии `state.json` для `streak`: пустая
  история, 1/3 красных дня подряд, смена зелёный→красный, дыра в истории.

## Устойчивость и алерты

Любой фатальный сбой (сайт не открылся, контракт снапшота изменился, Telegram
не принял пост после ретраев) алертит `TELEGRAM_ADMIN_CHAT_ID` напрямую —
`src/alert.ts` не зависит от facts/render и не переиспользует retry-политику
обычных постов: свой fetch, 10с таймаут, один ретрай, текст до 3500 символов.
Если алерт сам не ушёл — полный текст падает в stderr, exit code всегда 1.
Скип по идемпотентности и обычный dry-run **не алертят** — это ожидаемое
поведение, а не сбой. Токен бота нигде не логируется.

## Деплой на VPS

```bash
docker compose build
docker compose run --rm morning-post
```

`compose.yml` — one-shot сервис (`restart: "no"`), volume `./data:/app/data`
под `state.json`, все переменные — из `.env` рядом (`env_file`). Деплой самим
образом — тем же способом, что и сайт (GHCR + `docker compose pull`).

`Dockerfile` — на базе `mcr.microsoft.com/playwright:v1.62.1-jammy` (браузер и
системные библиотеки уже внутри). **Версия образа обязана совпадать** с
версией пакета `playwright` в `package.json` — при обновлении Playwright
править оба места одним коммитом, иначе на сервере тихо другой рендер
скриншота или вовсе "browser not found".

Системный cron на хосте с явной таймзоной:

```
CRON_TZ=Europe/Moscow
0 9 * * * cd /opt/morning-post && docker compose run --rm morning-post >> /var/log/morning-post.log 2>&1
```

Если `CRON_TZ` не поддерживается кроном на хосте — `0 12 * * *` (09:00 МСК =
12:00 Asia/Almaty) и всё равно передавать `TZ=Europe/Moscow` в контейнер:
дата в заголовке поста и ключ дня в `state.json` зависят от него, не от
таймзоны хост-машины. Перехода на летнее время в РФ нет, пересчитывать не
нужно.

## GitHub Actions

`.github/workflows/dry-run.yml` — только `workflow_dispatch` (ручной запуск
из вкладки Actions), без `schedule`: расписание живёт на VPS. Гоняет
`typecheck` + `test` + один `DRY_RUN=1` прогон против реального `SITE_URL` в
том же образе `mcr.microsoft.com/playwright:v1.62.1-jammy`, что и `Dockerfile`,
и прикладывает `./out` артефактом. Нужны репозиторные secrets: `SITE_URL`,
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_TARGET_CHAT_ID`, `TELEGRAM_ADMIN_CHAT_ID`.

## Тесты

```bash
npm run typecheck
npm test
```

Чистые функции (`facts.ts`, `phrases.ts`, `render.ts`, `alert.ts`, `state.ts`)
покрыты vitest-тестами на фикстурах, без браузера и без сети. `capture.ts` и
`telegram.ts` тестами не покрыты сознательно — Playwright и реальный Telegram
API сделали бы тесты флакующими; их корректность проверяется прогонами
(`npm run dry`, `npm run post`), не автотестами.
